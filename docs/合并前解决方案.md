# Vivid 三分支合并前解决方案

## 1. 背景与目标

当前远端有三个功能分支，各自实现了一个独立页面原型：

| 分支 | 现状 |
| --- | --- |
| `origin/LXT` | 已有 `Index` 底部 Tab 框架、作品列表/详情、mock 数据、公共组件与较完整的设计令牌 |
| `origin/ljh` | 首页视觉 + 相册选图入口，快捷功能区与近作区为静态展示 |
| `origin/CentralOfUser` | “我的” + 登录/注册/设置/协议页，表单校验完整，服务未接入 |

合并目标：

1. 以 `origin/LXT` 为集成基线，因为它已经具备 `pages/Index` 主框架和作品链路。
2. 最终形成三个一级 Tab：`首页`、`作品`、`我的`，启动页统一为 `pages/Index`。
3. 登录、注册、设置等作为独立路由页保留，不塞进 Tab。
4. 本次合并只解决“三套代码能整合、能编译、能跑通原型”，不接后端，不实现 AI 分割和真实调色保存。

## 2. 推荐合并顺序

新建集成分支，不要在任意一个开发分支上直接合并：

```bash
git checkout -b codex/merge-prep origin/LXT
```

推荐顺序：

```text
1. origin/LXT                        ← 基线
2. 合并 origin/ljh                   ← 先接入首页
3. 验证可编译、可运行后提交
4. 合并 origin/CentralOfUser         ← 再接入“我的”/登录/设置
5. 验证可编译、可运行后提交
6. 最后合并 origin/main              ← main 只有 PRD 文档，冲突风险最低
```

`origin/ljh` 与 `origin/CentralOfUser` 的公共文件大量重叠，建议不要同时合并，避免一次面对三份冲突。

## 3. 目标页面结构

```text
pages/Index.ets（MainTabs，唯一 @Entry 启动页）
├─ TabContent 首页  → components/home/HomePage.ets    ← 来自 origin/ljh
├─ TabContent 作品  → components/works/WorksPage.ets  ← 来自 origin/LXT
└─ TabContent 我的  → components/mine/MinePage.ets    ← 来自 origin/CentralOfUser

独立路由页（pages/*.json 注册）
├─ pages/WorkDetailPage
├─ pages/LoginPage
├─ pages/RegisterPage
├─ pages/UserSettingsPage
├─ pages/AppSettingsPage
├─ pages/UserAgreementPage
└─ pages/PrivacyPolicyPage
```

三个 Tab 内容都应是普通组件，不能各自带 `@Entry`。具体调整：

1. 把 `origin/ljh` 的 `pages/HomePage.ets` 迁到 `components/home/HomePage.ets`，去掉 `@Entry`。
2. `WorksPage` 已经是可复用组件，直接使用。
3. 把 `origin/CentralOfUser` 的 `pages/Mine.ets` 迁到 `components/mine/MinePage.ets`，去掉 `@Entry`。
4. `Index.ets` 增加三个 `TabContent`，底部 Tab 文案固定为：首页、作品、我的。

## 4. 入口与路由统一

### 4.1 EntryAbility

以 `origin/LXT` 版本为基底，最终保留：

- 沉浸式全屏布局。
- 系统避让区写入 `AppStorage`，统一命名为 `statusBarHeight`、`navBarHeight`，单位为 px。
- 窗口背景统一为宣纸色 `#DEDDD7`。
- `loadContent('pages/Index')`。

`origin/ljh` 的 `topAvoidHeight`（vp）不再使用，避免同一份数据两种单位并存。

### 4.2 main_pages.json

最终注册列表：

```json
{
  "src": [
    "pages/Index",
    "pages/WorkDetailPage",
    "pages/LoginPage",
    "pages/RegisterPage",
    "pages/UserSettingsPage",
    "pages/AppSettingsPage",
    "pages/UserAgreementPage",
    "pages/PrivacyPolicyPage"
  ]
}
```

被改成组件后的 `HomePage`、`Mine` 不再单独注册，避免出现“路由页和 Tab 组件两份实现”。

## 6. 设计令牌统一（第二阶段）

唯一来源：

```text
entry/src/main/ets/components/common/Theme.ets
entry/src/main/resources/base/element/color.json
```

`CentralOfUser` 的 `MaskSealPalette` 与 LXT `Theme` 的色值基本一致，迁移成本低。建议映射：

| MaskSealPalette | Theme | 说明 |
| --- | --- | --- |
| `paperBase` | `PAPER_BASE` | 宣纸灰 |
| `paperSurface` | `PAPER_SURFACE` | 浅纸白 |
| `ink` | `ON_SURFACE` | 正文墨色 |
| `inkMuted` | `ON_SURFACE_VARIANT` | 次级文字 |
| `primary` | `PRIMARY` | 深朱砂主色 |
| `sealRed` | `SEAL_RED` | 钤印红 |
| `outline` | `OUTLINE` | 描边 |
| `outlineLight` | `OUTLINE_VARIANT` | 浅描边 |
| `surface` | `SURFACE` | 页面表面 |
| `surfaceContainer` | `SURFACE_CONTAINER` | 卡片表面 |
| `error` | `ERROR` | 错误色 |
| `tertiary` | `TERTIARY` | 辅助色 |

迁移完成后：

1. 所有页面统一从 `Theme` 取色，不再引用 `MASK_SEAL`。
2. 清理硬编码色值：`#c8a4a0`、`#d8c8c4`、`#eadbd7`、`#957d7a`、`#f9e3e1`、`#d2a5a0` 等全部收口为令牌。
3. 逐个删除冗余文件：`entry/src/main/ets/common/Theme.ets`、`entry/src/main/ets/components/MaskSeal.ets`。
4. 删除文件遵循仓库 `AGENTS.md`，一次只删一个明确路径的文件，不做批量删除。

## 7. 功能边界

本次合并后仍然保留原样，不假装已实现：

- 登录、注册、验证码仍提示“服务暂未接入”。
- 设置项不持久化。
- 作品列表仍使用 `MockWorks`。
- 首页选图后仍只提示 Toast，`TODO` 保留为“跳转编辑页”。
- 作品详情页仍只展示 mock 数据，不继续编辑。

这些边界在 README 中写明，避免把原型当成已完成功能。

## 8. 验收清单

每个合并阶段提交前至少完成：

1. DevEco Studio 或 `hvigorw` 构建通过。
2. `AuthValidators.test.ets`、`List.test.ets` 通过。
3. 真机或模拟器启动后默认进入 `pages/Index`。
4. 底部三个 Tab 可切换，首页/作品/我的内容正常显示，状态栏避让正确。
5. 首页相册选择、取消、失败三种反馈正常。
6. 作品筛选、排序、详情跳转正常。
7. 我的 → 登录/注册 → 设置 → 协议往返和返回栈正常。
8. `git diff --check` 无空白错误。

## 9. 明确不做

- 不在这次合并中接后端账号服务。
- 不在这版实现 AI 分割、蒙版编辑、真实保存。
- 不做一次性的批量文件清理；冗余文件按 AGENTS 规则逐个删除。
- 不直接合并到 `main`，先合入 `codex/merge-prep` 验证后再讨论发布策略。
